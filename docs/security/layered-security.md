# Layered Security Architecture

This document outlines the defense-in-depth security blueprint implemented across ChattingApp's 10 structural layers.

---

## The 10 Layers of Defense

### 🛡️ Layer 1: Input Validation
- **Pydantic Validation:** All FastAPI endpoints validate incoming request body JSON against strict Pydantic schemas. Undefined or malformed parameters are rejected with a `422 Unprocessable Entity`.
- **Magic Byte Scanning:** File uploads undergo magic-byte signature checks in the media service rather than trusting user-supplied headers or extensions.
- **XSS Escaping:** Rich-text content undergoes sanitization. The frontend automatically escapes variables inside React JSX to prevent Cross-Site Scripting (XSS).

### 🛡️ Layer 2: Authentication
- **Firebase Auth Primary:** Secure verification of identity using Firebase token verification.
- **JWT Signature Checks:** Local signature verification fallback for offline resiliency.
- **Multi-Factor Authentication (MFA):** Database-backed Time-based One-time Password (TOTP) MFA (`pyotp`, `qrcode`).

### 🛡️ Layer 3: Authorization
- **Role-Based Access Control (RBAC):** Gated endpoints restrict administrative actions via `allowed_roles=['admin', 'moderator']` dependencies.
- **Resource Ownership Binding:** Handlers check `request.state.user_id` against the database resource's `owner_id` (e.g. before deleting posts or messages).
- **Group-Level Scope Rules:** Group settings updates, invites, and message deletion are validated against group memberships and roles.

### 🛡️ Layer 4: Session Protection
- **Refresh Token Rotation (RTR):** Single-use refresh tokens prevent token replay attacks. Replaying an old token results in immediate revocation of the entire token family.
- **Device Fingerprinting:** Tokens are bound to the client's `device_id` fingerprint. A mismatch immediately invalidates the token.
- **Secure Cookies:** In production, session state cookies are set with `HttpOnly`, `Secure`, and `SameSite=Strict` flags.

### 🛡️ Layer 5: Rate Limiting
- **API Request Throttling:** Backend middleware tracks IP addresses and authenticated users, enforcing limits (e.g. max 100 requests/minute for standard API calls, and 5 requests/minute for auth/registration paths).
- **WebSocket Reconnection Limits:** Limits connection rates to prevent reconnect-storming.

### 🛡️ Layer 6: Abuse Prevention
- **IP Reputation Scoring:** Requests from flagged VPNs, public proxies, or tor exit nodes are challenged or blocked.
- **AI-Driven Content Scanning:** Direct messages and feed posts undergo automated toxicity, spam, and NSFW checks before publication.
- **Shadow-Banning:** System administrators can shadow-ban users. Shadow-banned posts are visible only to the author, mitigating user abuse without inciting retaliation.

### 🛡️ Layer 7: Audit Logging
- **Immutable Log Ledger:** A dedicated `AuditLog` service records every authentication event, permission change, user suspension, and security error.
- **Blockchain Hashing:** Login histories and audit trails are structured as hash chains. Each audit record includes the hash of the preceding record, preventing tampering.

### 🛡️ Layer 8: Data Encryption
- **Transit Protection:** All network traffic is encrypted using TLS 1.3. Nginx rejects cipher suites with known weaknesses.
- **Rest Encryption:** Client caches in IndexedDB are encrypted using AES-256-GCM.
- **Backup Encryption:** Backups generated by users are encrypted client-side using Web Crypto PBKDF2 keys before upload.

### 🛡️ Layer 9: Infrastructure Hardening
- **Trusted Host Middleware:** The backend rejects requests where the `Host` header does not match the configured domain list.
- **Headers Middleware:** Enforces `Content-Security-Policy` (CSP), `X-Frame-Options: DENY`, `X-Content-Type-Options: nosniff`, and `Strict-Transport-Security` (HSTS).
- **Container Isolation:** Docker containers run under unprivileged user profiles with read-only root filesystems where applicable.

### 🛡️ Layer 10: Operational Monitoring
- **OTel Tracing & Prometheus:** Realtime monitoring of database pool usage, CPU spikes, request latencies, and exception rates.
- **Anomaly Detection Alerts:** Alerts trigger upon:
  1. A sudden spike in `401 Unauthorized` requests from a single IP.
  2. Multiple token family replay attacks.
  3. Database replica latency exceeding 1000ms.
